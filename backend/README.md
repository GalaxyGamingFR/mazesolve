# MazeMuse backend

Rust workspace: localhost simulator for RoboCup Junior Rescue Maze 2027 rules, with a Muse-powered
tuner. The HTTP contract is [`docs/API.md`](docs/API.md).

## Setup

- Rust >= 1.80 (`rustup update stable`).
- From this directory (`backend/`), nothing else to install.

## Environment variables

| var | default | meaning |
|---|---|---|
| `MM_PORT` | `8080` | server port (always bound to 127.0.0.1) |
| `META_MODEL_API_KEY` | unset | Meta Model API key; enables Muse (`/api/health` reports `muse: true`) |
| `MUSE_BASE_URL` | `https://api.meta.ai/v1` | Meta Model API base URL |
| `MUSE_MODEL` | `muse-spark-1.3` | model name |
| `MUSE_REASONING_EFFORT` | unset | reasoning effort passed to Muse |
| `RUST_LOG` | `info` | log filter |

Keys are read from the environment only and never logged.

## Commands

```bash
cargo fmt --all && cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo run -p mm-server            # :8080
cargo run -p mm-server --bin mm-schemas   # regenerate docs/schemas/*.json and generated fixtures
cargo run -p mm-cli -- demo       # end-to-end demo (later milestone)
cargo bench -p mm-sim             # perf gates (later milestone)
```

## Demo commands

```bash
cargo run -p mm-server
curl localhost:8080/api/health
curl localhost:8080/api/spec
curl -X POST localhost:8080/api/robots/validate -H 'content-type: application/json' -d @fixtures/robot_reference.json
cargo run -p mm-server --bin mm-schemas
```

## Layout

- `crates/mm-core`: wire types, rules, no I/O
- `crates/mm-server`: Axum server (`mm-server`) and schema/fixture dumper (`mm-schemas`)
- `docs/`: `API.md`, `schemas/` (JSON Schema per wire type)
- `fixtures/`: mock data for the frontend (`maze_small.json` and `replay_small.json` are hand-written; the rest are generated by `mm-schemas`)
- `rules_profiles/`: all rule numbers
